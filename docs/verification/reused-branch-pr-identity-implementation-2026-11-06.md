# Reused branch PR identity: implementation acceptance

Specification: [#139](https://github.com/danielbaars/anthracite/issues/139). Implementation: [#144](https://github.com/danielbaars/anthracite/pull/144), covering #140–#143. Baseline: public npm 0.6.11, source `1ae171c08a3e23ae3eb4b0274266a5a5f1dbdb1a`.

## Boundaries

The synthetic acceptance cases run public CLI processes against real temporary Git repositories and bare remotes. Only GitHub answers/effects are controlled at the external `gh` boundary. They do not claim live GitHub write acceptance. The additional live runtime probe inspected this implementation PR read-only and preserved its local head, metadata, index and worktree status. No user projects or active installation were changed. No live test PRs or full CI matrix were used.

## Resulting authority

- Inspection prefers a unique open PR. Without one, terminal history requires exact local-tip equality; ancestry and a reused name are insufficient. Stored hints and every returned candidate are validated, capped/inconsistent results refuse, and inspection never attaches or detaches metadata.
- Submit resolves open targets or proven absence before pushing. Terminal PRs never receive draft, role or footer writes. Local planned heads, bases and metadata remain guarded across confirmation, later branches and post-push effects. Confirmed effects are retained on refusal.
- PR-based cleanup requires fresh terminal state at the protected local head. Cleanup consent does not authorize discarding uncovered feature work. Independent existing local empty/merged proof and explicit selected-branch force authority remain distinct.
- A validated historical association may remain a status hint without proving the current local generation is landed. Sync can refresh a unique current open PR while preserving unmatched local work.
- Continuation checks remaining pinned cleanup before staging/replay. Genuine 0.6.11 records are generated by the published CLI, without editing saved records or ownership digests. Valid legacy records receive application-only verified proof; incompatible work preserves recovery.

## Delivery

The additional direct ordinary-CI selection runs four critical discovery/refusal cases; the installed-package selection retains all 23 representative cases, including actual 0.6.11 legacy production of recovery. The package campaign is bounded to five minutes and the single cheap CI job to ten minutes. Full validation remains manual and was not dispatched.

The package runtime smoke needs process visibility for its owned-process cancellation fixture. A sandboxed run could not observe the hook and exceeded the older campaign deadline; the isolated numeric-zero cancellation case passes with the necessary process access. Final package acceptance passed with that access and a supplied legacy executable: **23 scenarios plus one separate alias case**. Both commands, completion, curated files, real Git/MCP execution, numeric-zero cancellation and current/legacy recovery are covered by the [installed-package output](reused-branch-pr-identity-implementation-2026-11-06/installed-package.txt).

This is an unreleased source candidate. Publication and installation are separate operations.
