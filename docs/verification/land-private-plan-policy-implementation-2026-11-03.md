## Limits and publication scope

Successful absence verification is distinct from PR readiness. It requires exact eligible REST denial plus complete current private/admin/trunk/null-classic and empty/all-disabled inherited evidence. Active, evaluate and unknown states remain outside the alternate proof. Normal REST, classic-404 proof and all stricter combined/publisher requirements remain authoritative. Separate API reads and merge effects are not atomic; fresh guards and GitHub enforcement remain necessary.

The historical read-only observation demonstrates API availability and one disabled-rule shape. Controlled acceptance demonstrates the executable behavior against synthetic service responses and real Git effects. **No live GitHub landing acceptance or readiness of any real private PR is claimed.** No CI, full suite/matrix, Release, npm publication, live GitHub fixture/account/repository-setting changes or user-project mutation were performed. Direct rebase merging, confirmation, maintenance/publication scope, credits, compatibility and recovery format remain unchanged. Parent/ticket closure is through the one implementation PR; merge, release, active installation updates and any live acceptance remain separate authorization scopes.
