## Baseline and observed problem

The inspected source and published CLI baseline is Anthracite **0.6.6**, release commit [f03adc7075519b3c623e72e24ab6d8ce64c223e4](https://github.com/danielbaars/anthracite/commit/f03adc7075519b3c623e72e24ab6d8ce64c223e4). The user reported a noninteractive landing dry-run failing while reading applicable rules for a private repository. Its public error grouped the refusal under authentication or permission.

Read-only diagnosis established valid gh authentication and administrator repository access. The applicable-rules endpoint returned a structured HTTP 403 saying the feature requires GitHub Pro or a public repository. A branch read returned the requested trunk with `protected: false`; the classic-protection endpoint independently returned the same plan message. The authenticated-user response did not expose a plan name. The specification therefore does not claim a verified subscription name or use a guessed plan as authority.

A separate GraphQL request identified the same private repository, administrator visibility and the exact trunk, with an explicit null classic `branchProtectionRule`. Its unfiltered ruleset connection requested `includeParents: true`, returned one node, reported `totalCount: 1` and `hasNextPage: false`, and identified that node as a disabled branch ruleset. This is the reason an all-disabled inventory must be supported alongside an empty inventory.

The [anonymized observation transcription](evidence/land-private-plan-policy-spec-2026-11-03/observations.json) retains the decision-bearing response shapes. It is an explicitly sanitized transcription, not an unchanged raw capture or a synthetic test result. Repository/owner names, node IDs, cursors, user project paths and private PR/branch details are excluded or replaced. No credentials, authentication output, source files or private PR content are published.

These observations establish API availability for one real case. They do not establish PR readiness, successful landing, an accepted implementation or universal availability of the alternate API. No project files, refs, recovery, settings, rulesets, subscription, PRs or installation were changed. No live landing or CI was run.

## Primary API basis

- [GitHub's ruleset guide](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/managing-rulesets-for-a-repository) distinguishes feature availability from repository access and describes disabling rulesets without deleting them.
- The [GraphQL repository reference](https://docs.github.com/en/graphql/reference/repos#repository) exposes the ruleset connection, cursor pagination and `includeParents` for higher-level rulesets. The live GitHub schema was also inspected read-only to confirm that argument is available.
- [Get rules for a branch](https://docs.github.com/en/rest/repos/rules#get-rules-for-a-branch) returns active applicable rules from all configuration levels and excludes disabled/evaluate rules. The proposal does not reinterpret evaluate mode as active; it excludes it from this intentionally narrow alternate proof.

An unfiltered complete GraphQL inventory plus explicit disabled enforcement is the proposed independent evidence path. Its conservative acceptance contract is a design decision, not an undocumented assertion that every plan-denied repository lacks protection.

## Approved acceptance boundary

The owner approved the [full specification](../specs/land-private-plan-policy.md) scope and these test boundaries before writing:

- Public CLI processes with real temporary Git repositories/bare remotes and only controlled gh/GitHub responses.
- Preserving dry-run/refusal and terminal cancellation; actual synthetic landing, successor maintenance and recovery; full inherited pagination; changed policy on resumption or while waiting.
- Retained existing classic/ruleset policy guards and exact-head readiness protections; one existing MCP smoke and isolated npm delivery checks.
- Targeted Node/native selection and relevant local static checks. No CI, full matrix, live GitHub writes or user-project mutation.

Prior art: [policy CLI cases](https://github.com/danielbaars/anthracite/blob/f03adc7075519b3c623e72e24ab6d8ce64c223e4/apps/cli/test/commands/land_policy_cli.test.ts), [independent classic-absence cases](https://github.com/danielbaars/anthracite/blob/f03adc7075519b3c623e72e24ab6d8ce64c223e4/apps/cli/test/commands/land_ruleset_classic_cli.test.ts), [saved-plan comparisons](https://github.com/danielbaars/anthracite/blob/f03adc7075519b3c623e72e24ab6d8ce64c223e4/apps/cli/test/commands/land_resume_display_cli.test.ts), [bounded waiting](https://github.com/danielbaars/anthracite/blob/f03adc7075519b3c623e72e24ab6d8ce64c223e4/apps/cli/test/commands/land_wait_cli.test.ts) and the [external GitHub boundary fixture](https://github.com/danielbaars/anthracite/blob/f03adc7075519b3c623e72e24ab6d8ce64c223e4/apps/cli/test/lib/fixtures/land_gh_boundary.js).
