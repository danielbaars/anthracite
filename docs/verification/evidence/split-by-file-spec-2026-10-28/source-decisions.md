# File-split specification: source decisions

Read-only research, 28 October 2026. Canonical checkout: `3c5e9b7c2dce089d1add90e939d50d56989918f2`; product-source baseline: `3923b1088b29f02ce9d9e2d8da9fb52339889915`. No implementation or runtime tests performed.

## Established facts

- Official Graphite [command reference](https://graphite.com/docs/command-reference#gt-split) establishes `split`/`sp`, `--by-file`/`--file`/`-f`, repeated pathspecs, extraction into a new parent, and file mode's noninteractive exception. The [tutorial](https://graphite.com/docs/squash-fold-split#by-file-using-the---by-file-flag) explains retaining the original branch name to retain PR association. Neither page specifies naming collisions, multi-commit rewriting, empty remainders, rename endpoints, or rollback. Do not infer those from documentation.
- The [retained demonstration](https://github.com/danielbaars/anthracite/blob/3c5e9b7c2dce089d1add90e939d50d56989918f2/docs/research/split-by-file-demo-2026-10-28.md) establishes one mixed commit, a generated `feature_split` parent, reused subject, preserved feature/child trees, and unchanged unrelated branch. Its Graphite unmatched-path control changes raw index/internal metadata despite preserving logical state.
- Current [command](https://github.com/danielbaars/anthracite/blob/3923b1088b29f02ce9d9e2d8da9fb52339889915/apps/cli/src/commands/split.ts#L5) has commit/hunk only; the [action](https://github.com/danielbaars/anthracite/blob/3923b1088b29f02ce9d9e2d8da9fb52339889915/apps/cli/src/actions/split.ts#L23) requires prompting, can implicitly track an untracked source, and checks tracked dirt only.
- [applySplitToCommits](https://github.com/danielbaars/anthracite/blob/3923b1088b29f02ce9d9e2d8da9fb52339889915/apps/cli/src/lib/engine/engine.ts#L1081) keeps local `prInfo` only on the retained original name, publishes branches/metadata sequentially, and checks only source editability. It is a building block, not an atomic transaction.

## Recommended explicit product decisions

These are proposed contracts, not claims about Graphite. Subsequent probe findings supplied by the coordinating agent settle names/messages; its approved identity-retention decision makes all-selected an early refusal.

1. Define selection from the complete net tree delta between validated parent/base and original source tip. For selected changed paths, extracted-parent entries equal source-tip entries (including absence for deletions); every other entry equals the original parent. Rewritten original tip equals its original tree. Collapse multi-commit source changes into at most the documented generated commits; do not silently promise author, signature, original commit-boundary or SHA preservation. Use an oldest-to-newest full-message join separated by blank lines for both generated commits; single-commit messages remain exact, including body. Generated author and committer use current Git identity (coordinator-reported probe result).
2. Use Git pathspec matching, literal argv transport, and NUL-delimited paths. Repetition/overlap must not duplicate changes; support spaces, Unicode and `:(literal)` for names containing wildcard characters. [Git pathspec semantics](https://git-scm.com/docs/gitglossary#Documentation/gitglossary.txt-aiddefpathspecapathspec) include exclusions, which makes “union” inaccurate unless explicitly restricting supported magic. Choose and document repository-root versus effective-cwd interpretation. Recommend root-relative consistency with branch-wide operation. Treat rename endpoints as net delete/add entries unless probes justify a deliberate paired-rename policy; never make correctness depend on Git's similarity heuristic. Test old-only/new-only matches.
3. Preserve original branch name, checkout, and local PR identity; extracted parent starts without that identity. Do not contact GitHub or submit. Generate `<source>_split`, appending `_split` until the name is available (coordinator-reported probe result). No net matched changes must refuse before publication. Refuse all-selected before split effects: this explicit Anthracite decision preserves approved original identity without introducing an empty-branch model. The coordinator reports Graphite instead deletes the original branch in this case.
4. File mode must reject invalid/conflicting selectors, missing/empty patterns, trunk/detached/untracked/invalid source, existing interrupted operation, and staged/unstaged tracked dirt before split effects. Reject only interfering untracked/ignored paths; preserve unrelated files. Validate source and all mandatory descendants for frozen/worktree blockers before publication. Frozen unchanged ancestors remain usable anchors.
5. Require preserved source/descendant trees on ordinary success, parent-first chain/fanout restacks, unchanged unrelated stacks, clean tracked state, and return to original source. Commit IDs may change. Hook failure or conflict after publication may leave completed work. Report the phase, completed/remaining branches and exact next recovery commands; preserve hook/user files. Fresh-process `continue` must resume actual conflict state without repeating completed extraction; hook failures without an active rebase need a truthful explicit retry path, not fabricated `continue` support. Abort has bounded Git rebase scope, never universal split rollback. Preserve imported Graphite history/continuation formats; do not invent an undo feature.
