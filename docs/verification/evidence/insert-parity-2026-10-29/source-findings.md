## Selected parent and children

1. `create --insert` chooses current tracked branch (or trunk); `--onto/-o P` chooses that explicit tracked local parent instead. It snapshots **every direct tracked child** of P, not just the current chain, current child, first child, or a user-selected subset. No insert selector, confirmation prompt or child-choice path exists in this action. The children snapshot precedes branch-name validation, staging and branch creation. [create_branch.ts:24–52,168–215](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/actions/create_branch.ts#L168)
2. Both `--insert` and `-i` are booleans with default false; `create` aliases `c`. The help explicitly says all existing children of the selected parent become children of the new branch. `--onto` requires a string argument. [commands/create.ts:14–19,40–55](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/commands/create.ts#L40)
3. `getRelativeStack(...UPSTACK)` validates the parent as tracked or trunk. `getChildren` filters to `VALID` tracked children, recursively in existing cache child order; source does not impose a new sort. `checkoutNewBranch` uses the selected local ref as start point, explicitly preserves ignored files for `--onto`, and refuses detached invocation with `--onto`. [engine.ts:305–315,752–784](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/lib/engine/engine.ts#L752)
4. With no children the action returns after creation/optional commit; there is no reparent/replay stage. Without `--insert`, existing children remain siblings and only a usage tip is emitted. [create_branch.ts:75–99](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/actions/create_branch.ts#L75)

## Exact order of effects

1. Initial insert participant/dirty/path/worktree preflight.
2. Patch-input and branch-name/message preconditions.
3. Create/check out the new branch on P; for explicit `--onto`, preserve original index for possible commit-failure cleanup.
4. Repeat insert preflight after checkout/hooks, retaining the original selected children.
5. `--all` stages first (taking precedence over `--patch`); explicit-onto patch uses `addPatch`; ordinary patch goes through commit. Commit staged content, or leave an empty branch when none is staged.
6. Calculate affected descendant traversal and mandatory participants; persist structural insert role before parent changes.
7. Change **each original direct child's parent metadata** to the new branch, checking frozen participants before every child change.
8. Check remaining tracked dirt and interfering files again; restack the selected children and their descendants. Each branch uses its own recorded base and its new parent tip. Aligned branches return `REBASE_UNNEEDED`.
9. Clear continuation on success.

Sources: [create_branch.ts:28–73,102–164,218–276](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/actions/create_branch.ts#L102), [engine.ts:344–358,1180–1206](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/lib/engine/engine.ts#L1180), [restack.ts:39–67,70–188](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/actions/restack.ts#L39).

This is a commit-then-reparent-then-replay operation; source makes no transactional all-or-nothing promise.

## Terminal and noninteractive behavior

- Insertion scope is identical in terminal and pipe modes in this source: no insert-specific prompt exists.
- Name must be provided or derived from a commit message; missing both throws instead of prompting. Explicit name is sanitized; generated name uses configured prefix/date/message policy. [create_branch.ts:32–47](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/actions/create_branch.ts#L32), [branch_name.ts:27–57](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/lib/utils/branch_name.ts#L27).
- With staged input (or `--all` and status entries), no nonblank `--message` and `!canEdit` throws before creation. A supplied branch name alone suffices for an empty branch. `--patch` with unstaged changes and `!canPrompt` refuses; `--all --patch` bypasses that patch precondition. [create_branch.ts:30–47,227–242](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/actions/create_branch.ts#L30), [preconditions.ts:57–70](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/lib/preconditions.ts#L57).
- Policy defaults to interactivity only when stdin and stdout are TTYs; quiet and any nonempty `GRAPHITE_INTERACTIVE` disable it. Explicit interactive can allow an editor without TTY, but `canPrompt` still requires both TTYs. [interaction_policy.ts:9–25](https://github.com/danielbaars/anthracite/blob/9fa53077d9c7a52bc2b903799ab9b7a74da2d8ba/apps/cli/src/lib/interaction_policy.ts#L9).

## Failure effects and recovery

| Point of failure | Source-defined reached state |
| --- | --- |
| Initial insert preflight | No new branch, new commit or insert parent changes by this action. |
| Refreshed preflight after branch checkout/hooks | New branch and checkout/index/files remain; existing children have not been reparented. |
| New commit fails | If a participant became frozen, retain new branch/index/files. With explicit onto, if hook/external work changed prepared work state, retain new branch and checkout/index/files. Otherwise attempt return to original source branch for onto, restore original index if captured, and delete new branch. Cleanup itself may fail, producing a diagnostic. This is conditional cleanup, not universal rollback. |
| Participant becomes frozen after successful commit | Created branch and commit retained; parent loop has not yet begun if initial mandatory assertion fails. |
| Parent-change/replay failure | New branch/commit, already changed parents and completed restacks remain. Active-rebase case reports that raw rebase abort cancels only active Git replay. Non-rebase case instructs `an restack --upstack` from new branch after resolving blockers. |
| Genuine replay conflict | Shared restack saves remaining replay queue, current branch override, new base and rebase ownership, prints conflict instructions and throws. Fresh continue checks active/remaining mandatory participants before staging, continues active replay then queue. Success clears insert continuation. |
