# MCP cancellation and shutdown TDD receipt

Approved boundary: an independent official SDK client over stdio to the built public CLI, real local Git fixtures, and independent process/Git/lock observations. No engine mocks, private handlers, timer seams or client configuration changes.

- Active/queued cancellation red (`01-cancellation-red.log`): SDK client requests cancelled locally, but owned hook/grandchild work remained alive. Green (`03-cancellation-green.log`) after passing public request signals into the existing supervisor and removing cancelled queue entries. An explicit queue worker retains its active slot until child/group finalization; a removed waiter cannot release a later mutation early.
- Numeric-zero cancellation red (`05-zero-red.log`): the pinned official SDK's falsy request-ID guard ignored a valid cancellation. Green (`07-zero-green.log`) after the two-line CJS/ESM Yarn patch. The SDK still validates notifications, owns abort controllers and suppresses ordinary cancelled responses. Final probes cover both active and queued zero IDs, late/completed/unknown notifications and malformed cancellation during unrelated active work.
- EOF red (`09-shutdown-red.log`): closing stdin did not stop the server. Green (`11-shutdown-green.log`) after synchronous admission shutdown, queue discard and shared owned-process drain. The EOF driver uses official SDK framing over directly owned pipes and never sends fallback signals; SDK StdioClientTransport.close() therefore cannot mask a missing EOF handler.
- Final shutdown scenario includes EOF, server SIGINT, server SIGTERM and a closed client output pipe that forces EPIPE. Ordinary hook/grandchild groups stop; the server's direct child is independently observed/reaped. Unrelated processes/foreign cache and Git lock bytes survive. A real rebase conflict with deliberately staged resolution and continuation bytes is retained, and a new SDK session inspects it.
- Numeric-zero probes additionally force a stopped direct CLI leader and a matching owned cache lock. Before/after OS records and lock absence prove forced cleanup without inventing a runtime signal or rollback claim.

Final source/binary runs and their hashes are bound in receipt.json. The broad affected MCP controls were run before the last learning-text clarification; only that maintained string changed afterward, and final source/binary learning/registration and lifecycle tests were rerun. The original and final native binaries are retained with distinct hashes.

The SDK dependency remains pinned at 1.32.2. The patch changes only its invalid falsy guard to an undefined check in both distribution formats. CONTRIBUTING.md documents removal when upgrading to an upstream fix. The ticket worktree's private dependency cache was reconciled with network access and then verified by an offline immutable install. Shared global mirrors and canonical dependencies were not changed.

No push, PR, Actions/full matrix, live GitHub publication, release, global install or MCP client registration was performed. Validation host: macOS ARM64; Linux-specific zombie handling remains inherited from ticket 16 and was not exercised on this host.
