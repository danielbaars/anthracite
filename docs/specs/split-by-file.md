## Problem Statement

Anthracite can split a branch by commits or interactively by hunks, but cannot extract selected files into an independent prerequisite. A developer or agent must manually reorganize commits, branch tracking and descendants. The installed MCP integration correctly forwards CLI calls but cannot supply a missing file-mode workflow or answer interactive split prompts.

The retained demonstration establishes that Graphite 1.8.6 can split a mixed commit into a new parent and a remainder while preserving final source/child trees. Installed Anthracite rejects the same --by-file invocation. Additional probes establish multi-commit flattening, generated naming, overlapping selectors, file entry behavior, subdirectory pathspecs and genuine conflict continuation. They also expose Graphite behaviors Anthracite deliberately does not copy: deleting the original branch for a complete selection and silently skipping an occupied child after extraction.

## Solution

Add noninteractive file mode to split and sp using repeatable --by-file, --file and -f selectors. Extract a proper, nonempty subset of the current tracked feature branch's net committed changes into a generated parent branch. Rebuild the original branch as the remainder, retain its name/checkout/local PR identity, and restack the mandatory affected descendants with truthful conflict recovery.

Preserve the original source tip tree and, for initially restacked nonconflicting descendants, their tip trees. Refuse known unsafe inputs before split effects. A complete selection is an explicit early refusal rather than deletion of the original branch or creation of a new empty-branch model. Existing commit/hunk modes, global interaction policy, hooks, frozen/worktree protection and continuation compatibility remain authoritative. Existing MCP execution becomes able to use the new CLI mode without a server change.

## Implementation Decisions

1. **Command surface.** Add file mode to the existing split command and sp alias. --by-file, --file and -f are equivalent repeatable string-array selectors. Multiple values and repeated spellings form one ordered pathspec list; overlap never applies a change twice. Missing values, empty/whitespace-only values, NUL and malformed Git pathspecs fail clearly. Active commit/hunk and file modes are mutually exclusive; explicit false booleans do not activate another mode. Existing selectors and default commit/hunk interaction remain unchanged when file mode is absent. No source selector, custom generated-name/message flag, force override or new MCP tool is added.

2. **Source eligibility and operation directory.** File mode operates only on the physically checked-out, locally tracked, non-trunk source with a nonempty, linear own-commit segment above its recorded parent. Its recorded base must equal the current parent tip and be an ancestor of source; refuse an out-of-sync source with instructions to restack deliberately. An untracked source is refused rather than implicitly tracked. Reject detached HEAD, invalid tracking, unsupported merge history and an active rebase/merge/cherry-pick/revert or Anthracite continuation before repair or split effects. Existing global cwd parsing chooses the operation directory; read-only Git discovery identifies that directory's repository and worktree. Do not introduce a second global parser.

3. **Selection semantics.** Define changed entries from the complete net tree delta between the validated parent tip and original source tip, without rename inference. Match that delta with Git pathspec semantics from the effective cwd inside the selected repository. Root and literal magic and exclusions retain Git meaning; exclusions are not described as a simple union. Pass strings to Git literally with argument boundaries and use NUL-delimited path records. Invalid/outside-repository selectors fail before effects. Paths added and later removed within source history have no net entry change and are not selected. Preserve supported Git entry content, absence and mode, including binaries and symlinks; do not read blobs as text or follow symlink targets. If an unsupported path encoding or Git entry cannot be handled losslessly, refuse before effects rather than corrupt it. A source delta involving changed gitlink entries is refused; unchanged gitlinks remain ordinary unchanged tree entries. Submodule operations are excluded.

4. **Exact tree projection.** Let the original parent and source tip trees be the declared inputs. The extracted parent tree equals the original parent tree with exactly the selected changed entries replaced by their source-tip entries, including deletion when absent. Every unselected entry stays at its original-parent value. The rewritten original source tree equals its complete original tip tree, so its delta above the extracted parent contains precisely the remainder. A rename is a net deletion and addition at two independently selectable paths; old-only and new-only matches may place those endpoints on different branches. Do not depend on Git's similarity threshold. If a partial file/directory replacement would produce a structurally invalid selected tree, refuse before construction and ask for the dependent paths to be selected together. Never silently enlarge the selection. Use these tree rules, not patch output or the candidate's renderer, as the correctness contract.

5. **Empty selections and retained identity.** Refuse before construction/publication when no net changed entry remains selected, including a matching but unchanged file. Also refuse when the selection leaves no net remainder. Return an actionable nonzero diagnostic and retain refs, tracking, local PR identity, indexes, work and recovery state. This deliberately differs from measured Graphite complete-selection deletion and from its unmatched-selector index/metadata writes. Do not add empty-commit/empty-source behavior or general undo as an implicit dependency. The caller can choose a proper subset or use an existing explicit branch operation.

6. **History and generated commits.** A successful file split creates one selected commit on the original parent and one remainder commit on the selected commit, flattening the source's own linear commit segment. Both generated commits use the same message assembled from the original own-commit messages oldest to newest, retaining each body and joining them with one blank line after removing terminal newline runs. Preserve the normal final commit-message newline. Use the invoking Git author/committer identity and ordinary Git environment, consistent with the observed generated commits and existing commit behavior. Do not promise old commit boundaries, author identities, signatures, timestamps or OIDs; explain flattening in help. Existing commit mode remains the option for preserving boundaries. Already-restacked descendants keep their own messages and trees through ordinary replay; stale descendants receive actual current-source changes and any explicit user resolution, so their old tip trees are not guaranteed.

7. **Generated name and metadata.** Start with the source name followed by _split; while unavailable append another _split and choose the first safe valid local branch ref. Availability includes ref namespace conflicts, not just exact existing branch names. Never overwrite or retarget an existing branch; fail before effects if no valid candidate can be allocated. Recheck the expected source, parent, participant tips and candidate availability at structural checkpoints rather than overwriting concurrent work. Keep the original branch checked out at ordinary completion and retain its local PR identity and associated approved metadata. The new parent has no copied PR identity and starts editable. Preserve unrelated branch/status/PR data and existing legacy storage formats. No fetch, remote push, PR mutation or service lookup occurs.

8. **Read-only plan and early protection.** File-mode parsing, source/selector validation, name allocation and mandatory-participant planning must precede ordinary context repair that could write caches or refs. Validate the source and all mandatory descendants before constructing/publishing the split; mandatory replay segments must be linear, and unsupported merge participants refuse before effects; fail as a whole on frozen mandatory participants or foreign occupied worktrees, rather than applying generic skip behavior after source changes. The source's current worktree is allowed; unchanged frozen or occupied ancestors are read-only anchors. Tracked staged/unstaged changes refuse without automatic staging or stashing. Preserve unrelated untracked/ignored content and refuse checkout/replay collisions, including intermediate replay paths and directory/case/Unicode aliases covered by existing safety helpers. Early refusals preserve both main and linked-worktree indexes, dirty files, refs, tracking/frozen/PR data and continuation, including invalid opaque state that must not be silently repaired.

9. **Construction and extraction checkpoint.** Keep command parsing/output, file-selection/tree construction and structural publication/replay responsibilities distinct behind the existing command interface. Reuse existing Git, branch application, collision, hook and continuation mechanisms where they satisfy the contract. Prepare and validate both generated commits before publishing the extraction checkpoint; do not reset the user's working tree/index as a shortcut for planning. At that checkpoint the selected parent, rewritten source and their tracking relationship must describe the prepared trees coherently, retaining the original identity. Do not delete the original name. Do not silently overwrite unexpected ref movement. Necessary small operation-scoped metadata/context changes must remain backward compatible; a general transaction, journal or concurrent-lock redesign is excluded. Failure during publication must report actual reached refs/state and protect foreign work, not claim atomic rollback.

10. **Mandatory descendant replay.** Plan the selected source's complete tracked descendant scope, including fan-out, and replay in parent-first order. All required participants remain mandatory for this structural change; a frozen/occupied descendant must never turn into an unnoticed skipped success. Initially restacked descendants retain their final trees when no external hook or user resolution changes content. Valid already-stale descendants are allowed and replay from their recorded bases; they can legitimately conflict or gain previously unapplied parent changes. Leave trunk, unselected stacks, read-only anchors and foreign worktrees untouched. Finish on the original source with clean tracked work when successful, preserving unrelated untracked/ignored files.

11. **Phase-aware failure and continuation.** Distinguish preflight refusal, commit construction, extraction publication and descendant replay in diagnostics. Before the extraction checkpoint, a construction/hook failure must not publish the prepared split as successful; preserve hook/user effects and explain any cleanup or manual recovery needed. After the checkpoint, a failed replay may leave the completed extraction and earlier replays in place. Report completed/remaining participants, the actual active replay and the exact valid next command. A genuine Git rebase conflict returns a nonzero result with its unmerged/index/continuation state intact. Fresh-process continue resumes the current replay and remaining mandatory plan without constructing the split again; use existing base/ownership/departure mechanisms plus a minimal durable split role if needed. Recheck frozen status, worktree availability and expected refs before staging or advancing. A refused continue preserves staged resolution and recovery bytes. Return to the original source after successful completion. Hook failures without an active rebase get a truthful explicit restack/retry path, not fictitious continue support. External termination may prevent a final diagnostic; fresh inspection of actual state remains authoritative under the existing interruption contract. Raw Git rebase abort remains bounded to that rebase and does not undo the earlier split; no new global abort/undo command is introduced.

12. **Hooks, concurrent work and cleanup.** Retain the existing verify/no-verify scope and commit/replay hook behavior; do not bypass hooks merely to synthesize commits. Early validation happens before hooks. Detect a prepared-tree mismatch or new mandatory blocker at the appropriate existing checkpoint and report the reached phase rather than silently absorbing unexpected content. Hook effects are not promised rollback. Cleanup removes only proven owned temporary state and preserves foreign locks, Git locks, user files, staged resolutions and legacy continuation data. The command is not a filesystem sandbox or a guarantee against arbitrary external processes changing files between checks.

13. **Noninteractive and output policy.** File mode is usable with closed stdin, quiet and no-interactive, without a prompt, Anthracite editor, pager or automatic answer. Ordinary interactive execution uses the same deterministic file-mode policy rather than adding a selector UI. Normal success explains the created parent and replay outcome; quiet suppresses ordinary progress while retaining actionable errors/conflict information. Success means the whole mandatory operation completed. Existing MCP run_an_cmd receives ordinary CLI results in its unchanged envelope; cancellation/timeout keep their existing no-rollback lifecycle contract and do not introduce durable split jobs or automatic retries. Help and completion expose the aliases, repeatable selectors, cwd interpretation, flattening, complete-selection refusal and recovery limits.

14. **Delivery scope.** Deliver this feature in one implementation PR after ticketing, with linear history and retained upstream credits. Run the approved focused public cases locally on Node and an independently compiled native executable, plus affected existing controls. Allow only the existing cheap automatic CI. No full matrix dispatch/rerun, live GitHub publication fixture, release/tag/asset build, global installation or client registration is part of implementing this specification. This document publishes the approved contract and evidence, not an implementation result.

## Testing Decisions

Use one main product seam: invoke the built public CLI in real temporary Git repositories. Run the same accepted cases against Node and a separately compiled native binary, with no silent runtime skips. Reuse the existing split/editor, relation/cwd snapshot, structural/frozen/worktree, hook and continuation fixtures; add no engine mocks, in-memory stack model, private handler exports or test-only execution hooks. One small smoke uses the existing real MCP client helper at the already established stdio seam; do not create a new MCP tool, server harness or protocol matrix.

Good tests assert intended and refused persisted outcomes. Observe public branch/parent/PR information and independent Git refs, trees, complete messages, staged diffs, index/files, modes/binary bytes and real rebase state. Expected trees come from declared fixture entries or a deliberate direct-Git control, not candidate rendering or the same projection helper as production. Early refusal snapshots include affected and linked worktrees plus opaque protection/metadata/recovery state. Successful writes assert exactly their intended scope; partial failures assert reached state rather than a universal no-change claim. No full command/flag/file-type Cartesian matrix is required.

T12 deliberately starts with a valid recorded but stale child base; after resolution, its expected tree follows the declared resolution and current source changes, not its old tree. Existing frozen structural controls and replay-file collision helpers provide the prior art for early protection. Existing split commit/hunk and modern alias/completion scenarios provide regression controls; the existing MCP execution fixture supplies the sole MCP smoke.

Retain concise per-case Node/native results, source and binary identities, representative failure/continuation records and hashes. Build, typecheck and uncached relevant source/test lint must pass. Required validation is the accepted feature cases and affected controls, not the entire repository suite or paid CI matrix. Any optional broader check needs a concrete new failure or unresolved concern to justify it.

## Out of Scope

- Interactive file-picking UI, custom split names/messages, automatic staging/stashing, automatic submission or an additional MCP tool.
- Preserving original source commit boundaries/authors/signatures/OIDs, preserving a stale child's old tree after applying current parent changes, or synthesizing source/descendant merge-topology preservation.
- Deleting the original branch on complete selection, new empty-source/empty-commit modes, general undo/abort, transaction journaling, broad metadata repair or a new concurrency model.
- Live GitHub PR creation/update/review/merge, Graphite accounts/backend services, authentication redesign or PR migration. Local original PR identity preservation remains in scope.
- Generic hook sandboxing, rollback of arbitrary hook effects, global process cleanup, new cross-platform path machinery or full platform certification. Reuse existing safeguards and retain their limits.
- Submodule-changing file splits and arbitrary non-UTF-8 path-byte support; refuse unsupported selected entries safely rather than silently corrupting them.
- Redesigning existing commit/hunk modes, unrelated log parity, absorb, sync/get/submit modes or other deferred features.
- Implementation, ticket publication, full CI matrix runs, releases/assets/tags, global installation and client configuration during this specification task.

## Further Notes

The owner approved these six public testing groups on 28 October 2026 and requested the complete English specification and GitHub issue. This is approval of the test boundary and feature contract work, not evidence that implementation acceptance has passed.

The [original demonstration](../research/split-by-file-demo-2026-10-28.md) pins Graphite 1.8.6 and installed Anthracite 0.1.1-dev.20261027211215. The [specification research](../research/split-by-file-spec-research-2026-10-28.md) and [evidence manifest](../verification/evidence/split-by-file-spec-2026-10-28/manifest.json) retain the additional probes, independent tree/identity/recovery observations and source decisions. Graphite observations include multi-commit flattening, joined messages, invoking identity, repeated _split naming, pathwise rename projection, cwd-relative selection, complete-selection source deletion, occupied-child skipping and a real conflict/continue sequence. They do not establish all unmeasured modes or safety properties.

Anthracite deliberately refuses complete selections to retain the original branch/PR identity, refuses occupied/frozen mandatory plans before extraction, and preserves early-refusal state rather than reproducing Graphite's observed unmatched-path internal writes. These are explicit product decisions. Selection projection details, body normalization, safe ref namespace allocation and publication checkpoints make the implementation contract precise; not every detail was measured in Graphite.

Primary references are Graphite's [command reference](https://graphite.com/docs/command-reference#gt-split) and [split tutorial](https://graphite.com/docs/squash-fold-split), and Git's [pathspec glossary](https://git-scm.com/docs/gitglossary). Runtime evidence is the pinned shipped executable; available Anthracite source explains current limitations and reusable mechanisms. Source inspection alone is not runtime acceptance. Keep the historical incomplete demonstration capture unchanged and distinguish it from the new completed probes.
